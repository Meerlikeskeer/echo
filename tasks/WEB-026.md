### Implementation and boundaries

`run.command --transcribe` starts the Swift receiver and a separate TypeScript worker using existing Node/tsx tooling. The receiver publishes the pinned session and monotonic, durable audio receipts; the worker processes only that session. A completed receipt no longer regresses to a partial prefix during receiver restart. Provider delays and worker failures cannot block device download/capture; local worker failures let reception finish.

Private `processing.json` binds jobs to immutable metadata, saves attempts before requests, caps each chunk at four attempts, recovers interrupted outcome-unknown jobs, and reuses successful transcripts without remote calls. Live/corrupt worker locks refuse concurrency; dead-PID locks recover. Audio hashes are rechecked before processing. Responses must match identity, validate through the domain stitcher, and explicitly acknowledge transcription-only mode. Authentication/input/identity refusals exhaust the job safely; network failures get bounded backoff. Raw audio and SD originals remain.

Chunk text files plus `transcript.json`/`transcript.txt` retain original timed source provenance and conservative overlap semantics. Missing and exhausted transcripts are marked; final requires explicit device completion and all expected valid transcripts. Device COMPLETE refers to audio only; the launcher separately reports transcription status and returns nonzero for partial processing. No observed session can imply finality.

The default recording API still returns transcript plus notes. Explicit transcription-only mode skips notes generation and uses a different in-process ledger key. Existing server provider configuration, including the notes group, remains required; no new vendor or infrastructure. Owner Basic access credentials come from private environment configuration; provider keys stay on the web server. Only HTTPS or loopback HTTP is accepted, redirects are refused, and credentials never enter arguments, receipt/journal files or logs. Lost responses/cold starts can repeat remote work; this is not exactly-once.
