## WEB-017 — Lecture note guide

**Status:** Implemented and verified by test; a real lecture transcript has never been through it · **Branch:** `feat/WEB-017-lecture-notes` · **Dependencies:** WEB-006, WEB-007

**Acceptance:** A session-length transcript reaches the notes endpoint without being refused or truncated, and comes back as a note guide — the course where the recording identifies it, the argument in sections, terminology as the speaker used it, open questions — with any gap in the recording named rather than written across.

### The three defects, in the order they bite

**1. A lecture could not reach the endpoint.** `isRevisionInput` refused a transcript over 24,000 characters with `400 bad_request`. An hour of speech is roughly 55,000. The endpoint that exists to summarise a session refused the only kind of session anyone wants summarised.

**2. Where it did not refuse, it truncated in silence.** Both generators did `transcript.text.slice(0, MAX_TRANSCRIPT_CHARS)`. Notes for a fifty-minute lecture would describe its first twenty minutes, correctly, with nothing anywhere saying the rest existed. The fix is not a larger cap — a larger cap that still truncates silently is the same defect further away. Echo now sends the whole transcript and refuses past its bound, and lets the configured model refuse what exceeds its own window, because a refusal is visible and a truncation is not.

**3. The schema was a meeting summary.** Key points and action items flatten a lecture's argument, its terminology and its unresolved threads into one shape. `SessionArtifacts` gains `course`, `outline`, `terms` and `openQuestions`.

**And one thing that was already known and thrown away.** The stitched transcript's gaps arrived in the request and were used only to compute the revision. Notes for a session missing four minutes read exactly like notes for a complete one. `describeGaps` converts them to minutes and states them to the generator, ahead of the transcript.

### Verification

- `npm run check` exit 0 in a clean clone: `check:tracked`, `tasks:check`, lint, typecheck, 182 unit tests, production build, 11 production HTTP tests, 4 self-host parity tests. Node 22.23.2, npm 10.9.8.
- New behavioural tests: a 55,000-character transcript is accepted where the old bound refused it; `course` is optional but its key is not, and a blank string reads as not identified rather than costing a whole set of notes; outline and term objects are validated as strictly as the flat fields, unknown nested keys included, with a headingless section and an empty section both refused; gaps are described in minutes and `capture-unconfirmed` is excluded because it means no completion record was saved, not that audio is missing; an over-long transcript is refused before any credential is used, with zero requests made; the whole transcript reaches the request body and the gap and partial-status context precedes it; the instructions ask for the lecture fields and still carry the untrusted-data and no-lookup rules.

### Not verified

No real lecture transcript has been through this. Nothing here establishes that a model returns a good outline, that `course` is identified correctly when a lecturer names their module, or that `[unclear]` marking behaves on genuinely garbled speech — all of that is fixture and unit evidence. `maxDuration = 300` is declared but has never been approached: no generation has taken more than a few seconds. The vendor is unchanged; if the owner points the notes port at a large-context model, that model's behaviour on a full lecture is its own acceptance.

### Next

Owner sets the notes model's environment variables to something whose context window covers a lecture, then generates notes from one real session and reports whether the outline is worth reading and whether the course was identified. The format is deliberately in one place — `ARTIFACT_INSTRUCTIONS` in the adapter, and the schema in `artifacts.ts` — so iterating on it is a prompt change plus a validator change, not a redesign. WEB-013 (opt-in research) is what would turn `researchTopics` and `openQuestions` into cited reading; nothing here looks anything up.
