## WEB-009 — Recording workspace and session history

**Status:** Implemented; final verification and browser acceptance in progress · **Branch:** `feat/WEB-009-recording-workspace` · **Dependencies:** WEB-004, WEB-007

**Acceptance:** List, search and reopen browser-local recordings and artifacts with
accurate partial/processing/blocked states; rename recordings persistently; offer
Start new Echo and the device-style recorder; deterministically organize completed
short recordings as Quick Notes and longer recordings as Sessions with an override;
retain original audio, retry controls, provider disclosure and single-owner access.

### Scope and decisions

Base: `main` at `7cd7c17`, including merged ENG-022. The owner reported the hosted
`.echo` import/transcription flow works, and prioritized usable website UI before
wireless device sync. ADR-024 expands this existing history task to the requested
workspace rather than combining unrelated tasks on one branch.

New browser captures always use the bounded, overlapping session engine. Automatic
category is a transparent duration rule, not a claim to recognize lecture versus
meeting content. Clean completion plus at most one minute means Quick Note; anything
longer or unconfirmed is Session. Labels can be overridden without rewriting capture
metadata or triggering another provider call. Legacy Quick Note suggestions remain
readable; new recordings use the existing general notes pipeline. Nothing schedules
reminders. Device wireless sync is deferred until this UI work is accepted.

Manual names/type preferences use validated per-session localStorage keys. The audio
queue and saved session guides are unchanged. History is specific to browser and
origin, not a cloud account. Automatic names use the opening transcript phrase.
Names do not claim the device's recording date; no timestamp is invented from its ID.

### Verification and handoff

Initial clean-clone `npm ci` passed. Local `npm run check` passed tracked-source,
generated-table, lint, typecheck and unit stages, then failed with EPERM removing
`.next/types`. A separate fresh checkout built successfully with `npm run build`;
that does not retroactively make the full local check pass. Python controller tests
exited 1 with a Python 3.9 unittest RecursionError.

Independent read-only review found tab switching cancelling notes, inaccessible
historical clip results, and concurrent import/capture selection. Fixed: notes stay
mounted across view switches, original results are available in a disclosure, and
import saving prevents capture start. Initial CI exposed smoke checks depending on
old screen wording and a server-rendered marker. The new server workspace landmark
is shared by all smoke checks; authentication and asset assertions stay intact.

Browser: production-build home visually inspected at desktop and 390px mobile width
with synthetic owner/fixture providers. Real browser `.echo` upload remains blocked
by automation file access permission. No real microphone or provider calls performed.
Final CI, measured floor, further browser evidence and PR handoff follow below.
