## ENG-021 — The deployed check did not know about the second Route Handler

**Status:** Implemented and verified against a production build; awaiting owner review · **Branch:** `eng/ENG-021-deployed-check-artifacts` · **Dependencies:** ENG-010, WEB-007

**Acceptance:** `npm run test:deployed` verifies every Route Handler on the deployed origin, and a new one cannot go live unverified.

### The gap

WEB-007 added `POST /api/sessions/artifacts` and added it to the **local** production suite's unauthorized path matrix. It did not add it to `scripts/deployed-smoke.mjs`, which is the only check that sees what a hosting platform does *in front of* the origin. So a new production access surface was about to be deployed with no deployed-origin verification at all.

That is precisely the failure ENG-010 wrote this script for. Its own header says the local suites structurally cannot see a platform answering before the application runs. A second endpoint inherits that risk and got none of the coverage.

**The rule, so it does not recur: every Route Handler belongs in the deployed check, and a new one is not deployed until it is there.**

### What changed

`scripts/deployed-smoke.mjs` now checks `POST /api/sessions/artifacts` the way it already checked `POST /api/recordings`: an anonymous request must be challenged with 401, an owner request carrying a body that is not a session transcript must not be answered 200, and no error body may contain the owner password. The success line says *both Route Handlers* rather than naming one.

### Verified, by execution rather than by reading

The script accepts a loopback origin, so it can run against a real production build. That is how these assertions were exercised.

| Command | Exit | Observed result |
| --- | --- | --- |
| `npm run build`, then `next start` on `127.0.0.1:3111` with fixture providers and synthetic credentials, then `node scripts/deployed-smoke.mjs http://127.0.0.1:3111` | **0** | *"challenges anonymous requests, refuses wrong credentials, serves the page and 9 compiled assets to the owner only, hides diagnostics, and guards both Route Handlers."* |
| Same run, with the artifacts assertion inverted to expect 200 | **1** | Failed at that assertion. The new check is reached, evaluated, and the endpoint really answers 401. |
| `npm run check` | 0 | 161 unit / 161 pass / 0 fail, 9 production HTTP, 4 self-host parity. |

**What the loopback run does not prove.** The script says so itself: *"checked over loopback, not a real certificate: this does not verify the deployed transport."* It confirms the assertions are correct and the endpoint is gated by Echo. Whether a CDN edge answers for it before Echo runs can only be seen against the real deployed origin, which is owner-only.
