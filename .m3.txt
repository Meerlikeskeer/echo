feat(ENG-014): stop STATUS.md from causing merge conflicts

STATUS.md's update protocol required every task to write the same three
regions -- the In flight section, one row of a shared fifteen-row table,
and the verification snapshot. Git conflicts when branches touch the same
region, so the protocol did not merely permit collisions, it mandated
them. 29 of the 61 commits on main touched STATUS.md (48%), and the two
volatile sections were 92 of its 192 lines (also 48%). Half the file was
the half everyone had to rewrite.

The cost was mostly invisible, because the usual escape was stacking
branches rather than resolving conflicts: DOC-003 under ENG-013 under
DOC-004 under this task, four deep. AGENTS.md warns against stacking for
unrelated and better reasons. One rule in the repository was pushing
directly against another.

A second failure came from the same shape. Because In flight was shared
and easy to append to, finished work accumulated there instead of moving
somewhere durable. It reached 51 lines and simultaneously said
"provisioning started, nothing deployed yet" and, three paragraphs later,
"ECHO IS DEPLOYED". Removing it surfaced a second stale claim sitting in
the task table: a row asserting ADR-009 and ADR-010 were "Accepted, not on
main" when both have been on main for some time.

Recorded as ADR-015. The three regions move:

  In flight -> status/in-flight/<TASK-ID>.md, one per active task,
  created before work starts and deleted in the pull request that
  finishes it. Separate files never conflict.

  The verification snapshot -> the floor (72/7/4/16) stays in STATUS.md
  and changes rarely and deliberately; per-run numbers belong to the task
  that ran them.

  The task table -> generated by scripts/status-table.mjs from the
  **Status:** lines already in TASKS.md, which was always the real source
  of truth. npm run check fails when the two disagree.

The new check was made to fail on purpose, two ways, because a check that
has only ever passed proves nothing. A hand-edited row: exit 1, naming
TASKS.md as the source of truth and npm run status:table as the fix. A
removed marker: exit 2, naming the marker. Both restored; status:check
returns exit 0 on 29 tasks and runs inside npm run check.

None of the version-control discipline in AGENTS.md is relaxed. STATUS.md
is still the first and only file every session must read, the protocol
still applies in full, and the counts are still a floor. This changes
where status is written, not whether it is.

Verified on this branch, Node 22.23.2 / npm 10.9.8, Python 3.9.6:
check:tracked 0, status:check 0 (29 tasks), lint 0, typecheck 0, 72 unit
with 71 pass and 1 fail, production build 0, 7 production HTTP all pass,
4 self-host parity all pass, 16 controller tests OK.

The single unit failure is the known worktree one: output file tracing
still points at the repository root in both cases, which asserts the
checkout is named echo. Because check halts there, the four later steps
were run individually, which is where those numbers come from. This
branch changes nothing under apps/ -- git diff --stat 96a1b2a HEAD --
apps/ is empty -- so the unit suite is byte-identical to DOC-004's, which
ran 72 pass 0 fail in a checkout named echo. The floor holds.

Base is docs/DOC-004-deployed-check-passes, not main, and declared:
main lacks DOC-004 and ENG-013 (#20 and #19), and restructuring STATUS.md
from main would have conflicted with both across most of the file -- the
exact problem this removes, and a fourth instance of it.

Merge order: #19, then #20, then this one.
