## The prerequisite that is easy to miss

**Auto-merge requires branch protection with at least one required status check.** It is not an independent switch. With no required check a pull request is immediately mergeable, and GitHub rejects the request to enable auto-merge rather than merging early. If the owner turns on *Allow auto-merge* and nothing happens, this is why.

## A finding this task turned up, which belongs to ENG-015

`selfhost-container` now triggers on `pull_request`. **A pull request opened by `secrets.GITHUB_TOKEN` does not raise `pull_request` events** — GitHub suppresses them to prevent workflow recursion — and `open-pull-request.yml` opens every pull request with exactly that token. So the container job likely never fires on an auto-opened pull request, whether or not it is a draft. ENG-015's handoff attributes the absence to draft status; that may not be the whole cause.

This is the same constraint that made `pull-request.yml` trigger on `push` rather than `pull_request` in the first place, which ENG-007 got right.

**Not yet confirmed.** Check the Actions tab for pull request 26 and see whether `Self-hosted container` ever ran from a `pull_request` event. The handoff carries an optional path-filtered `push` trigger that restores the coverage if it did not.
