# WEB-007 — Structured artifacts

**Branch:** `feat/WEB-007-structured-artifacts` · **Base:** `main` @ `f68ccca`

## What this is

Turn a stitched session transcript (WEB-006) into one validated set of session
artifacts — title, summary, key points, action items and **research topics** —
bound to the exact transcript revision they were generated from. REQ-005 is the
requirement. `ARCHITECTURE.md` § *Provider boundaries* already states the LLM
contract as "Transcript + schema → validated artifacts", so this extends the
existing `notes` port. **No stack decision is made or changed, and no new port.**

## The design decision that shapes everything else

**Artifacts are accepted only when their revision equals the transcript's
current revision.** The obvious alternative — order two revisions and keep the
newer — cannot work, because the revision is a content hash and hashes do not
order. Requiring an exact match makes a stale overwrite impossible by
construction rather than by comparison: a generation that started from an older
transcript simply does not match the transcript on screen, so it is discarded
without ever being compared.

A second, separate rule handles two generations racing for the *same* revision,
which the first cannot distinguish: each carries a monotonic `generation`
assigned when it starts, and a lower one never replaces a higher one. It is not
consulted across revisions, so artifacts matching the current transcript always
win, whatever generation the stale ones carried.

## Two negative controls, and what the second one found

Disabling the equality rule failed **exactly** the two stale-transcript tests,
which is what a load-bearing test looks like.

The second control disproved a claim in my own first draft. A test asserted that
length-prefixed revision encoding prevents a forged revision; it passed with the
prefixes removed, because every record contributes a fixed number of fields and
both counts are encoded, so the naive delimiter was already collision-free given
the surrounding structure. The prefixes were kept — they do not depend on
anything around them, which is what survives the next variable-arity field — but
the comment and the test now claim only what is demonstrated.
