# WEB-007 — Structured artifacts

**Branch:** `feat/WEB-007-structured-artifacts` · **Base:** `main` @ `f68ccca`

## What I am attempting

Turn a stitched session transcript (WEB-006) into one validated set of session
artifacts — title, summary, key points, action items and **research topics** —
bound to the exact transcript revision they were generated from, so a malformed
provider response is rejected and a slow generation cannot overwrite artifacts
made from a newer transcript.

REQ-005 is the requirement. `ARCHITECTURE.md` § *Provider boundaries* already
says the LLM contract is "Transcript + schema → validated artifacts", so this
extends the existing `notes` port rather than introducing a new one. **No stack
decision is being made or changed.**

## The design decision that shapes everything else

**Artifacts are accepted only when their revision equals the transcript's
current revision.** The obvious alternative — order two revisions and keep the
newer — cannot work, because the revision is a content hash and hashes do not
order. Requiring an exact match makes a stale overwrite impossible by
construction rather than by comparison: a generation that started from an older
transcript simply does not match the transcript now on screen, so it is
discarded without ever being compared.

A second, separate rule handles two generations racing for the *same* revision,
which the first rule cannot distinguish: each carries a monotonic `generation`
number assigned when it starts, and a lower one never replaces a higher one.
Both are valid for that transcript, so this only prevents a late arrival from
undoing a newer retry.

## Scope

In: the domain type, the revision function, the validator, the acceptance rule,
the fixture adapter, the `openai-compatible` adapter, and tests for all of it.

Out: opt-in external research (WEB-013 — this task produces *suggested topics*
and performs no research, which is REQ-005's explicit separation), history
(WEB-009), and retention (WEB-010).
