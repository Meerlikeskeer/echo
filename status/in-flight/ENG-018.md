# ENG-018 — `npm run check` cannot pass in a worktree, and the reason is a folder name

**Branch:** `eng/ENG-018-worktree-verification` · **Base:** `main` @ `f68ccca`

## What I am attempting

`apps/web/tests/next-config.test.ts` asserts `config.outputFileTracingRoot?.endsWith("echo")`.
A worktree's root is `.claude/worktrees/<name>`, so the assertion fails on the
directory's name while `next.config.ts` is correct in both places — it derives
the root from `import.meta.url`, which resolves properly wherever the checkout
sits. Replace that assertion with one that tests the property ENG-012 actually
cares about.

## Why this is worth its own task

Two agents cannot work on this machine at once. They share one dependency tree,
and a clean install in one deletes the tree the other is reading. Worktrees fix
that completely, because each gets its own `node_modules` — **except that a
worktree cannot run the full check**, so all verification funnels back through
the one shared checkout.

That funnel is currently jammed: the main checkout's `node_modules/.bin` is
empty at the repository root and under `apps/web`, every package is present, and
both agent sandboxes are denied the symlink and delete operations needed to
relink. Confirmed as a sandbox restriction, not a filesystem one: both
directories are owned by the user with owner-write set, and this session's own
worktree has identical ownership and is fully writable.

So this one assertion is what stands between the current serialized workflow and
two agents verifying independently in their own worktrees.

## What must not be weakened

ENG-012 exists because `output: "standalone"` moved the file Vercel's
`onBuildComplete` hook reads, and the build died *after* compiling successfully.
The comment on this test is explicit that these assertions are the only thing
between a green local suite and a production build that fails on the platform.

The tracing-root assertion guards a different failure from the other two: Echo is
an npm workspace with hoisted dependencies, so tracing from `apps/web` emits a
bundle whose imports resolve to nothing — invisible at build time and caught only
when the emitted server is started. The replacement must still catch that, and a
negative control has to prove it does. **A change here that is merely permissive
is a regression, not a fix.**

## Done

The assertion now requires the tracing root to be the **workspace root**: its
`package.json` must declare `apps/web` as a workspace, and `apps/web` must
resolve inside it. The other two ENG-012 assertions, which keep
`output: "standalone"` off on Vercel, are untouched.

`CLAUDE.md`, `AGENTS.md` and `STATUS.md` all stated the old limitation as fact.
All three are corrected, and `AGENTS.md` now connects the fix to its own
concurrency rule: a worktree has its own `node_modules`, so two contributors
never share a dependency tree.
