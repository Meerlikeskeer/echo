# ENG-019 — Stop the process from generating merge conflicts and locking agents out

**Branch:** `eng/ENG-019-conflict-free-task-records` · **Base:** `eng/ENG-018-worktree-verification` @ `f8a7429`

**This branch is stacked on ENG-018 deliberately, and the pull request says so.**
It needed a worktree that can run the full check in order to verify itself, and
that is exactly what ENG-018 delivers. **Merge PR #32 first, then this one.**

## Done

Three root causes, one fix each. The full reasoning is in `tasks/ENG-019.md`.

1. **Files every task must edit** → records split into `tasks/<TASK-ID>.md`,
   index generated and `merge=union`, `TASKS.md` reduced to stable prose,
   table removed from `STATUS.md`.
2. **A test count no task could compute** → `npm run floor` measures it.
3. **A tracked `.env.example`** locked sandboxed agents out of any fresh
   checkout → untracked, re-added as `env.example`, `.gitignore` exceptions gone.

Plus `HUMAN_TESTING.md`, at the owner's request.

## Verified

`npm run check` exit 0 in a worktree: **161 unit / 161 pass / 0 fail**,
**9 production HTTP**, **4 self-host parity**. `npm run floor` measured and wrote
those same counts. `npm run floor:check` exit 0. Controller suite untouched and
confirmed at 16 tests, OK.

Two negative controls, both with observed exit codes:

- Floor set above the real counts → `npm run floor:check` **exit 1**, naming the
  suite that fell.
- Task heading disagreeing with its filename → `npm run tasks:build` **exit 2**,
  naming the file.
