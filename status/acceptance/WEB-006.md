# WEB-006 frozen acceptance

Independent acceptance setup, before implementation. Tests are synthetic and do not certify browser recording or IndexedDB behavior. The coordinator freezes these files before the builder starts. No new dependencies or changes to existing checks.

## Domain contract

`apps/web/src/lib/recording/stitching.ts` exports `stitchSession(input)` with this public shape (additional fields are allowed):

```ts
type Completion = { sessionId: string; chunks: readonly AudioChunk[] };
type Input = {
  sessionId: string;
  chunks: readonly { metadata: AudioChunk; transcript?: Transcript }[];
  completion: Completion | null;
};
type Output = {
  sessionId: string;
  text: string;
  status: "partial" | "final";
  sources: readonly {
    chunkId: string; sequence: number; segmentIndex: number | null;
    originalText: string; startMs: number; endMs: number;
  }[];
  segments: readonly {
    text: string; startMs: number; endMs: number;
    sourceIndexes: readonly number[];
  }[];
  gaps: readonly {
    reason: "capture-unconfirmed" | "missing-chunk" | "missing-transcript" | "invalid-input";
    sequence: number | null;
  }[];
};
```

Session timestamps are already normalized by provider adapters. Never add the chunk offset twice. Sort independent of arrival order without mutating inputs. A source preserves original segment text and timing; a text-only or unmatched full-transcript fallback uses `segmentIndex: null` and chunk bounds as a coarse envelope, never as verified word timing. Every rendered segment references its sources; deduplicated rendering references both original segments.

Only deduplicate whole segments wholly contained within the actual adjacent-chunk overlap, with matching normalized text and agreeing time intervals. Exact timestamp matches must deduplicate; a narrow documented tolerance is optional. Text normalization may fold case, punctuation and whitespace. Do not invent word timestamps, deduplicate ambiguous broad segments, or remove repeated speech outside the overlap. Retain unmatched transcript.text content; conservative duplication is preferable to lost speech.

Missing first/interior/expected final chunks and absent transcripts are explicit gaps. Capture evidence absent means partial even for a contiguous successful prefix. Invalid identities, sequences, metadata, completion manifests or nonfinite/reversed times fail closed with `invalid-input`, never throw away the rest of the session or finalize. Source content must not enter an error message.

Final requires a successfully stopped capture manifest and exactly its valid expected chunks with valid transcripts, no gaps, and consistent metadata. The completion manifest is generated only after capture ends successfully and is saved durably; it cannot be inferred from currently available rows. Capture failure and legacy rows without evidence remain partial. Completion is stored in an IndexedDB `sessions` store through a version 2 migration preserving existing `chunks` rows. Reopening must recover completion evidence, and a save failure cannot publish it as durable.

## Completion persistence seam

`apps/web/src/lib/recording/session-completion.ts` exports async `persistSessionCompletion(captured, save)`, where `captured` is `{ session: Session, chunks: readonly PlayableChunk[] }` and `save` accepts `Completion` and returns `Promise<void>`. Return the saved manifest only after save resolves; return null without saving for recording/failed capture. Reject invalid successful-capture metadata, empty capture, or save failure. The recorder calls this seam using captureSession.finished and the IndexedDB adapter; checking only the seam does not certify the hook wiring.

## Presentation and independent review

`apps/web/src/app/session-transcript.tsx` exports `SessionTranscript({ transcript })`, accepting the domain output. Render “Session transcript”, “Partial” or “Final”, source chunk numbers (one-based), session timestamps, and readable missing chunk/transcript information. Render all provider text through React text nodes. Recorder groups results by session and uses this component, including recovered sessions. Existing notes stay explicitly per-chunk and disclosures remain visible; WEB-007 owns session artifacts.

The same file exports `SessionTranscripts({ entries, completions })`, where entries are the domain input chunk array and completions is a readonly Completion array. This is the grouping boundary actually used by Recorder. Group sessions independently, associate only their own completion manifest, and include rows lacking transcripts. SSR tests exercise this boundary with multiple recovered sessions; they do not certify native browser capture or storage.

Frozen behavioral tests cover ordering, verified overlap/provenance, repeated speech, broad ambiguity, gaps, retry completion, invalid data, text-only recovery, source immutability, finalization persistence, and escaped presentation. Independent checker additionally reviews actual capture-to-storage-to-recovery integration and migration, existing verification counts, and continued incremental uploading. Native browser acceptance remains unverified unless actually executed.
